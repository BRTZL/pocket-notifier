---
title: App API
description: The oRPC procedures the mobile app uses, served at /api/rpc.
---

The app API is `appContract` in `packages/contract/src/app.ts`. The apps call it through the typed oRPC client at `/rpc`, signed in with their better-auth session. Every procedure requires a session except `invites.preview`.

```ts title="apps/native/utils/orpc.ts (after M1)"
import type { ContractRouterClient } from "@orpc/contract";
import type { AppContract } from "@notifier/contract";

export const client: ContractRouterClient<AppContract> = createORPCClient(link);

const inbox = await client.messages.list({ unreadOnly: true });
```

## Procedures

| Namespace | Procedure | What it does |
| --- | --- | --- |
| `me` | `get` | The signed-in user |
| `projects` | `list` | Projects the user is a member of, with role, subscription, unread count; includes the private General project (`personal: true`) |
| | `get` / `create` / `update` / `delete` | Manage one project (`update` and `delete` need `owner`). `iconUrl` sets any HTTPS image; `null` clears it |
| | `setIcon` | Upload the project's icon (`owner`; General too). See below |
| | `setSubscription` | Subscribe, unsubscribe, mute |
| `features` | `list` | A project's features, optionally one `status`, most recent activity first |
| | `create` | New feature, idempotent by slug (`owner` or `publisher`) |
| | `updateStatus` | `active`, `done` or `archived` (`owner` only) |
| `members` | `list` / `add` / `update` / `remove` | Manage a project's members (`owner` only, except `list`) |
| `messages` | `list` | Inbox, or one project with `projectId`; `unreadOnly` filter |
| | `get` | One message with read state |
| | `markRead` | By IDs, or everything up to a message |
| | `publish` | Same rules as the public publish, for "send test message"; takes an `attachmentId` |
| | `delete` | Remove a message (`owner` only) |
| `responses` | `create` | Ack or reply from a `reply` action |
| | `list` | Responses to a message (`owner` or `publisher`) |
| `tokens` | `list` / `create` / `revoke` | The user's access tokens; `create` returns the secret once |
| `invites` | `list` / `create` / `revoke` | Invites the user created |
| | `preview` | Public: what an invite link grants, for the sign-up page |
| `devices` | `list` / `register` / `rename` / `remove` | The user's phones; `register` upserts by push token |

## Project icons

<Status kind="decided" /> `projects.setIcon({ id, contentType, data })` takes the image as base64 in JSON, so the React Native client needs no multipart:

- `contentType` is `image/png`, `image/jpeg` or `image/webp`, and the first bytes must match it; anything else is `BAD_REQUEST`.
- At most `PROJECT_ICON_MAX_BYTES` (256 KB) decoded. The app resizes to a 256 px square first.
- The server stores it in R2 as `icons/<project id>/<sha-256 prefix>-<random>.<ext>` (a new key for every upload), sets `iconUrl` to `https://notifier.bartuozel.com/api/icons/<project id>/<file>` and deletes the icon it replaces. It returns the updated `MyProject`.

`GET /api/icons/<project id>/<file>` serves the image without a session, with `Cache-Control: public, max-age=31536000, immutable` (a new image gets a new file name), `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'`.

The project icon is the conversation icon everywhere: conversation summaries and the push payload use the project's `iconUrl` first, then the message's `conversation.iconUrl`.

## Errors

Every procedure can fail with `UNAUTHORIZED`, `FORBIDDEN` and `NOT_FOUND`. Some procedures declare more:

- `projects.create` and `members.add` can return `CONFLICT`.
- `responses.create` can return `CONFLICT` when the person has already responded to that action.
- `messages.publish` can return `TOO_MANY_REQUESTS`.

The typed client exposes them as `ORPCError` with a known `code`, so the apps can show a specific message instead of a generic failure. See [Errors](/docs/api/errors).
