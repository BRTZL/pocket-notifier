---
title: Publish
description: Send a message to a project, with priority, tags, actions and attachments.
---

```http
POST /v1/projects/{project}/messages
Authorization: Bearer nt_...
Content-Type: application/json
```

The token's owner must be an `owner` or `publisher` of the project, and the project must be in the token's scope.

## Examples

curl -X POST "$NOTIFIER_URL/v1/projects/backups/messages" \
  -H "Authorization: Bearer $NOTIFIER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"body":"Nightly backup finished in 4m12s"}'

<Tab value="From an agent">

  "title": "Needs your decision",
  "body": "Which database for the cache layer?",
  "priority": 4,

  "clickUrl": "https://t3.example.com/threads/abc123",

## Priority

| Value | Name | On Android |
| --- | --- | --- |
| 5 | urgent | Pops up, long vibration, can bypass Do Not Disturb |
| 4 | high | Pops up on screen |
| 3 | default | Sound and vibration |
| 2 | low | Silent, listed in the shade |
| 1 | min | Silent, collapsed, no status bar icon |

Each level is its own [notification channel](/docs/mobile/notifications#channels), so users can change how it behaves in system settings.

## Actions

Every action has a `label` (up to 40 characters), an optional `key`, and `clear`, which dismisses the notification after the action runs. If `key` is left out, it becomes the action's index (`"0"`, `"1"`, …). Replies refer to it.

<Accordions>
  <Accordion title="view: open a URL" id="action-view">
    ```json
    { "type": "view", "label": "Open PR", "url": "https://github.com/acme/app/pull/42" }
    ```
    Opens the URL in the browser, or in another app if it is a deep link.
  </Accordion>
  <Accordion title="http: send a request from the phone" id="action-http">
    ```json
    { "type": "http", "label": "Approve", "url": "https://hooks.example.com/approve/42", "method": "POST", "body": "{\"ok\":true}" }
    ```
    The phone sends the request in the background. `url` must be HTTPS. `method` is `GET`, `POST` (the default), `PUT` or `DELETE`. `body` is up to 1,024 characters.

    <Callout type="warn" title="Open: no secrets">
      There is no `headers` field. Everything in an action is stored and sent to every subscriber's phone, so a secret in it would leak. Use an unguessable URL, or a server-side action later. <Status kind="open" />
    </Callout>
  </Accordion>
  <Accordion title="reply: acknowledge or answer" id="action-reply">
    ```json
    { "type": "reply", "key": "ack", "label": "Got it" }
    ```
    With `input: false` (the default), tapping the button records an `ack`. With `input: true`, Android shows a text field in the notification. `placeholder` sets its hint, and up to 3 `quickReplies` appear as one-tap suggestions. Each person can respond to an action once.
  </Accordion>
</Accordions>

At most 3 actions fit on an Android notification; the rest appear only in the message screen. <Status kind="open" />

## Conversations and features

Every conversation is a feature. A message with `conversation` is filed under the project's feature for `conversation.id`, which is created on first use; a message without one goes to the project-level thread, `p:<projectId>`. The same rule applies to the REST API, the app API and MCP, so all three put the same conversation in the same thread.

- **Slug.** An `id` that is a valid feature slug once lowercased (`[a-z0-9][a-z0-9-]{0,62}`) is the slug, and an existing feature with it is reused as it is. Any other `id` is turned into one: accents removed, lowercased, everything else becomes `-`, cut to 63 characters (`org/repo` becomes `org-repo`). If that slug already belongs to a feature with a different name, `-2`, `-3` and so on is appended.
- **Name.** A new feature is named `conversation.title`, else `id`. An existing feature keeps its name.
- **Stored as** `conversation = { id: <feature slug>, title: <feature name> }`, in the thread `c:<slug>`. Each message moves the feature's `lastMessageAt`, which orders `features.list`.

A tap on the notification opens that thread. The `clickUrl` is an Open button on the message there, and an action on the notification.

## Projects

The project in the URL must already exist. Publishing to an unknown project returns `404 NOT_FOUND` instead of creating it, so a typo cannot create a project nobody is subscribed to. Projects are created in the dashboard or the app. <Status kind="open" />

## Attachments

<Status kind="decided" /> One file per message. Attaching takes two steps: upload the file, then publish with its ID. Agents on MCP use [`create_upload`](/docs/api/mcp#create_upload) instead of the first step.

<Steps>
<Step>

### Upload

```bash
curl -X POST "$NOTIFIER_URL/v1/projects/ci/attachments" \
  -H "Authorization: Bearer $NOTIFIER_TOKEN" \
  -F "file=@report.html;type=text/html"
```

```json
{ "id": "att_01jd8x7q3n1p5s8u0w2y4a6c8e", "expiresAt": "2026-11-21T12:00:00.000Z" }
```

`multipart/form-data` with the file in a field named `file`; the part's `filename` and `Content-Type` become the attachment's name and type (no type: `application/octet-stream`). The token needs publish rights on the project, checked before the body is read. The file streams to R2, so it is never held in memory whole.

</Step>
<Step>

### Publish

```json
{ "title": "Coverage report", "attachmentId": "att_01jd8x7q3n1p5s8u0w2y4a6c8e" }
```

</Step>
</Steps>

The upload must be yours, in the same project and not used by another message, or the publish is a `400`. Uploads not used within 24 hours are deleted (`UNUSED_UPLOAD_TTL_MS`). The cap is 95 MB per file (`ATTACHMENT_MAX_BYTES`, just under Cloudflare's 100 MB request limit); larger files get `413 PAYLOAD_TOO_LARGE`.

### Download

`message.attachment` has `id`, `name`, `contentType`, `size`, `kind` and `url`, and `expiresAt` (the message's: the file is deleted with it). `kind` is `image`, `video`, `pdf` or `file`, from the content type; the apps show an inline image, a video player, a PDF viewer or a file row.

`url` is `https://notifier.bartuozel.com/api/attachments/<id>/<token>/<name>`. The token is random (about 190 bits), so the URL works without a session (notification pictures, video players, sharing) until the message expires; treat it like the message itself. The route:

- sends `Content-Type`, `Content-Length` and `Content-Disposition`: `inline` for image, video and PDF, `attachment` for everything else, with a safe file name;
- supports `Range` (`206 Partial Content`, `416` past the end), so video players can seek;
- sends `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'`, plus `sandbox` for everything but images, so an uploaded HTML or SVG file never runs scripts on notifier's origin;
- answers a wrong token, an unused upload or an expired message with the same `404`.
- sends `Cache-Control: private, no-cache`, so a cached copy is revalidated and a deleted file stops being served.
