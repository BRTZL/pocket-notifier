## Screens

<Accordions multiple>
  <Accordion title="Inbox" id="inbox">
    All projects, newest first. Each row shows the conversation avatar (with the sender badge), or the project's avatar when there is no conversation. Unread messages have a dot; priority 4–5 show a marker. Pull to refresh. A filter chip row offers **Unread**, plus one chip per tag seen recently. Swipe a row to mark it read. Opening a message marks it read.
  </Accordion>
  <Accordion title="Message detail" id="message">
    Title, body, project, time, tags, attachment preview with download, every action (including those beyond the 3 that fit on the notification), and the responses so far if the user may read them.
  </Accordion>
  <Accordion title="Projects" id="projects">
    Projects the user is a member of, the private **General** project included, with unread count and subscription state. A project opens on its **Project thread** (notifications sent without a feature) and its **Features**, each with a status chip (`active` first, then `done`, then `archived`). A feature opens its thread. Owners see **Settings** for members, default priority and retention.
  </Accordion>
  <Accordion title="Settings" id="settings">
    Account and sign out; notification setup (permission state, a link to each channel's system settings, the Do Not Disturb override for urgent messages); devices; access tokens with copy-once secrets; invites.
  </Accordion>
  <Accordion title="Invite sign-up" id="invite">
    Opened from `notifier://invite/<code>` or the web link. Shows `invites.preview` (who invited you, which projects), then the sign-up form.
  </Accordion>
</Accordions>

## Deep links

| Link | Opens |
| --- | --- |
| `notifier://conversation/<projectId>/<key>` | A thread; `key` is `c:<feature or conversation id>` or `p:<projectId>`, URL-encoded. Used by notification taps |
| `notifier://project/<projectId>` | The project screen: its features and project-level thread |
| `notifier://invite/<code>` | Invite sign-up |
